\section{The Minimum Viable Deployment}
\label{sec:vision}

This section states what has to exist on a vehicle, and why the observation had
to change before anything could be built.

\noindent\textbf{Two layers, two sensors.}
The deployment separates two decisions that earlier formulations combined. The
advisory layer decides a desired speed for the super-segment the vehicle is on.
The safety layer decides whether that speed may be shown. They read different
sensors, and neither sensor can do the other's job. A traffic API reports
aggregate speed, free-flow speed and a congestion index per road segment. It
contains no individual vehicles, so it cannot report a leader distance, a
follower gap or a lane distribution. A forward camera is the opposite. It
measures the vehicle ahead and reports nothing about the network.
Table~\ref{tab:layers} states the split.

\noindent\textbf{Why the observation had to change.}
The published policy reads \texttt{[density, num\_lanes, avg\_speed, avg\_gap,
input\_rate, exit\_rate]} per super-segment. Four of those six are vehicle-level
ground truth in the published implementation, and a vehicle has no access to
them. The gap is the mean of each vehicle's follow distance. The entry and exit
rates are set differences over the vehicle identities present one minute apart.
The density is counted over the vehicles on the segment. A traffic API
returns \texttt{speed}, \texttt{freeFlow}, \texttt{jamFactor},
\texttt{confidence} and \texttt{traversability}~\cite{here_traffic_api}. The
deployed observation is therefore five fields per super-segment: \texttt{speed},
\texttt{free\_flow} and \texttt{jam\_factor} from the feed, and \texttt{lanes}
and \texttt{length\_km} from the map. The reward is unchanged. Training is
centralized, so it may use privileged information, and it keeps the published
form on ground-truth density. Only the state the vehicle reads is restricted.

In the simulator the feed is not available, so \texttt{jam\_factor} is computed
as $\mathrm{clip}(10\,(1 - \mathrm{speed}/\mathrm{freeFlow}), 0, 10)$. The
operator does not publish its formula and folds in incident data this project
does not have. That expression is therefore a stated model rather than a
measurement, and it is the one place where the simulated observation and the
deployed observation are not the same quantity.

\noindent\textbf{Why not aggregate from local sensing.}
A vehicle could in principle reconstruct segment-level state from its own
sensors and those of its neighbours. That needs either vehicle-to-vehicle
exchange, which is untested in this deployment, or a server that aggregates. The
second option removes the reason for the work. If a central server aggregates,
the centralized design is already available and simpler. Querying a traffic API
per vehicle is also simpler to operate than having vehicles talk to each other.
An earlier formulation of this project put per-vehicle quantities into the
policy's input and then required the feed to restore them, which it cannot. In
the design reported here the per-vehicle quantities stay where they are
measurable, and they feed the safety layer only.

\noindent\textbf{Decentralized execution is an identity.}
The policy's input is the whole network's state, and the policy is a
deterministic argmax over three speed fractions. Every vehicle that holds the
same weights, reads the same map and queries the same feed computes the same
action for the same super-segment. Decentralized execution therefore reproduces
centralized execution by construction, and no experiment is required to
establish it. What does differ on a road is staleness.
Section~\ref{sec:discussion} states which part of that this system can measure
and which part it cannot. The query is small. Twelve super-segments at five
features is sixty numbers per decision, and the decision interval is 60\,s. The
feed is queried by corridor or by circle, so one request covers the whole extent
and the number of super-segments does not change the number of requests.

\noindent\textbf{What the vehicle must therefore carry.}
Five things, and no more. A network definition that names the super-segments and
their edges. A traffic-feed query bounded by that network's extent. A policy
trained on that network. A local sensor set for the safety layer. A display. The
list of what it must not carry is shorter. There is no connection to the
throttle, the brakes, the steering or the vehicle bus, and no server inside the
control loop.
